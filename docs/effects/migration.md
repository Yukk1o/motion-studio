# 工程v2与插件版本

新建工程写入 `version:2`。读取v1工程时缺失的 `layers[].effects` 默认空数组，插件依赖默认空；迁移不会生成效果实例或修改原有动画、素材、摄影机。导入ZIP和JNI创建工程都执行迁移。v1声明了效果的异常数据会拒绝，未知未来版本也拒绝。

v2实例保存 `id/plugin/effect/version/hash/enabled/seed/params`，参数保存自己的类型、范围、可动画性与关键帧。`plugin_dependencies` 从全部实例生成去重排序的精确依赖，包括禁用实例；执行和导出只要求启用实例可用。读工程不自动安装插件，也不删除缺失插件的参数。

`.aem`以及现有`.motion`工程包仍只有project.json与工程素材，插件由App私有目录的 `<SHA256>.msfx` 文件提供。共享工程时需要单独交付匹配的包；版本号相同但字节不同不会被当成等价依赖。前端不要自行重写版本或hash来消除错误。

安装完整校验后原子落盘，同版本同hash重复导入幂等，同版本不同hash拒绝。每次加载会把当前内置版本持久保存，App升级后旧内置包仍能解析旧工程；内置库因此也必须按语义版本增加版本，不能修改已发布版本的字节。禁用状态保存于disabled.json。内置包可禁用，不能卸载。

升级是显式命令：保留实例ID和顺序，重建默认参数、移除原参数关键帧并重置种子，整个操作可撤销。新旧版本共存，首次交付没有自动参数迁移。前端在操作说明中告知重置行为，参考frontend-integration.md的upgrade请求。

导出创建独立工程会话并加载固定的Registry和Arc包字节；运行中不刷新注册表。现有会话保留原引用，卸载文件不会破坏已经冻结的导出；以后创建的会话会报告缺失依赖。正式输出预检包含隐藏图层的启用效果，逐帧计划继续校验动画后的参数与资源能力。超过设备能力时导出报错，不缩小半径、裁切外扩或跳过效果。

回退到只支持v1的旧App会拒绝v2；保留升级前备份。若确实需要降级，开发者必须显式删除全部效果与依赖、改写版本，并告知用户画面会改变，不能悄悄在保存时降级。


图层片段与效果共用工程格式 v2。v1 迁移同时添加默认全长 timeline 和空效果链；已有 v2 图层片段及 XYZ 独立轴轨道按原数据保留。效果键时间使用有符号图层局部帧，UI 编辑命令使用合成帧，转换规则见 frontend-integration.md。裁剪、移动、分割不能删减效果参数键；效果依赖由所有图层实例重新汇总，分割复制实例不会重复依赖记录。
