# 合成图规模与渲染预算

合成文档支持最多 256 个节点（含当前主节点）、16 个节点的嵌套路径（含根），以及从任意节点出发最多 1024 个静态展开实例。静态展开计入禁用、范围外和重复源引用，用于限制循环、深度和指数级依赖。

当前帧最多采样 64 个合成实例（含根）。只遍历片段范围、可见性、不透明度和子合成源时刻允许的分支，因此大素材库不必同时分配所有子合成纹理。现有视频解码器数量、128 MiB 图层纹理和 64 MiB 效果临时纹理预算继续独立生效；合成数量不等于同时活跃资源数量。

能力来自 `capabilities.composition_api`，前端使用返回值决定创建入口，而不写死 32 个合成：

```json
{"max_compositions":256,"max_depth":16,"depth_includes_root":true,
 "max_instances":1024,"max_render_instances":64}
```

`max_instances` 保持静态源展开的含义；它不能用作 GLES 帧包节点上限。帧包只包含已采样实例，继续使用版本 1；工程格式保持版本 8。旧工程无需迁移。

文档节点、深度、静态展开超限返回 `resource_limit`。当合法文档在某帧超过 64 个活跃实例时返回 `render_resource_limit`，包含合成 ID、源帧、所需实例数和上限；预览显示错误，正式输出失败。宿主不静默忽略余下图层或缩小资源。

图校验使用借用的节点与记忆化统计，避免复制整份工程或展开指数级路径。合成列表反向引用一次建立；可引用列表只检查增加一条源引用后的图，不为每个候选创建编辑器和撤销快照；插件依赖扫描只借用图层。声音遍历借用同一节点图，混合整数帧率保持有理时刻到绝对 48 kHz 样本边界；有理数中间值约分，精度预算超限时返回 `audio_time_limit` 和合成／图层定位。

连续、倒序和随机寻帧复用仍活跃且源身份未变的子合成 `Scene`、矢量和蒙版缓存。每帧更新动画与效果，恢复原始图层 ID 后重新分配实例别名；引用替换和参数变化会使对应缓存失效。退出当前帧的子合成缓存释放，避免整个素材库长期占用渲染内存。

验证使用独立生成的数据：错峰引用的 97 节点文档、深层混合帧率、重复源、静态展开边界、环、保存／重开／打包、原子失败、GPU 随机寻帧和前端超过 32 节点的创建。分辨率使用普通手机画面与小型像素对照，不依赖用户工程或私有素材。

GLES 对照同时覆盖 Shake 的混合帧率重复引用。部分 GLES 编译器会将超过 `INT_MAX` 的 `uint` 字面量误读为 `INT_MAX`，导致同一时间和种子的随机位移不一致；宿主通过共用的 Naga 编译器将此类字面量改为高低 16 位组合，覆盖原生 wgpu/GLES 预览与 GLSL 导出，保留完整的 32 位值。此处理在编译时完成，原 WGSL、参数布局、效果包字节与版本／哈希保持原值。

导出器在原生捕获后恢复自己的 EGL 上下文。原生与 GLES 导出的矢量 MSAA 都在线性 RGBA 目标上绘制并解析，再由 GPU 转换为合成使用的 sRGB 纹理，避免解析时平均编码颜色而使边缘变暗；解析纹理进入临时预算并按尺寸复用和释放。
