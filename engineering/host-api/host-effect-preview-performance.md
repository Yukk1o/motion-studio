# 光效与模糊的预览性能：后端交接

此分支针对 4K 视频叠加放射光线、发光、边缘发光、光条、星芒、定向模糊时的预览开销。适用于内置及导入包的普通 Image 效果；没有新增前端页面。工程、`.msfx`、SDK、渲染计划协议和已安装插件版本不变。

## 问题和处理

过去预览目标按合成尺寸建立，而非 Surface 的实际显示尺寸。效果临时纹理只乘合成的整体预览比例，未考虑图层的缩放：4K 图层缩小放入 1080p 合成，效果仍可能在 4K 上运行。放射光线每个输出像素采样 64 次，定向模糊的有效非零参数采样 128 次；其他光效也有多 pass、多方向采样。

自动、均衡、经济预览现在先将合成等比例放入物理 Surface，再应用既有档位比例。不会放大小合成。固定 High 保留旧的全合成、全图层效果密度，供需要检查细节的用户显式选择。

普通 2D 图层再按投影矩阵的最大像素密度选择 1、1/2、1/4、1/8、1/16 档位。使用最大奇异值处理旋转、镜像、非等比缩放及父级产生的剪切；微小浮点误差不触发档位抖动。3D、透视、调整图层、子合成引用及含粒子/镜头光效等 Scene 生成器的效果链保留合成整体密度规则，仍受合成预览尺寸约束。子合成内部普通 2D 图层可继续应用预览密度策略；矢量栅格使用对应图层的效果密度。图层位置、锚点、关键帧、效果的像素单位及逻辑外扩边界保持原值。

共享纹理池按实际 pass 大小分配，最终绘制使用该图层有效区域的 UV 比例，防止不同效果分辨率的图层互相拉伸或读取池中的空白。稳定档位下复用纹理和 pipeline；移除全部效果释放临时纹理。64 MiB scratch 限制和设备尺寸检查继续生效，超限报告错误；不裁切输出、不缩小参数。

有 timestamp query 的设备即使未开启诊断录制，也异步测量合成/效果及呈现 pass。四个 32 字节回读槽复用，槽忙时跳过，无帧图像回读、无逐帧 GPU 等待。关闭录制保留自动预览的 GPU 测量。对于不支持 timestamp 的设备，自动策略纳入 acquire/present 超出一个 FIFO 帧预算的等待，忽略普通 VSync 等待。此替代信号不能区分所有设备的 GPU 与调度压力。

## 前端接口

继续使用 `NativeBridge.previewMode(id, mode, thermal)`，模式 ID：0 自动、1 High、2 均衡、3 经济。原有热状态和自动降档阈值不变。若工程大于画布，自动模式的 High **档位**也会适配画布；只有用户指定的 High **模式**请求完整合成分辨率。

`NativeBridge.previewInfo(id).data` / `state.data.preview` 新增：

| 字段 | 取值和含义 |
| --- | --- |
| `effectResolution` | `projected_2d`：允许普通 2D 效果按占屏密度处理；`full_layer`：固定 High 使用原密度规则 |
| `surfaceBounded` | 是否启用画布约束策略；Surface 尚未连接时暂以合成尺寸报告 |
| `gpuTimingActive` | 当前 Surface 已创建可用的异步 GPU timer；不代表诊断正在录制 |

已有 `width`、`height` 表示当前策略请求的内部渲染尺寸，不能再写死为合成的 1 或 2/3。`state.data.graphics.renderWidth/renderHeight` 为已经建立的目标尺寸；切换模式后两者可能直到下一帧才一致。Surface 的物理尺寸继续使用 `graphics.width/height`。`profiling`、`gpuTimestampSupported` 的原含义不变。

示例：3840×2160 合成，1080×608 Surface，自动初始档位为 1080×608，均衡为 720×405，固定 High 为 3840×2160。保留当前呈现、视频 pending 重试和 `lastPresentedFrame` 的约定，参见 [视频预览接口](host-video-preview.md)。

暂停预览仍按所选模式呈现。PNG capture、MP4 的冻结/JNI/GLES 渲染计划继续使用原完整效果规则，不使用 `build_preview` / `encode_preview`。High 或正式输出超出资源预算仍会报告错误；例如全分辨率 4K 放射光线的多个 RGBA 临时纹理可能超过 64 MiB，此分支不解除该正式输出限制。

## 回归和可复现测量

- `cargo test --locked -p motion-render --test effect_preview_density`：预览尺寸、GPU/等待信号降档、旋转/镜像/非等比缩放、Scene 生成器回退、混合密度的池 UV、透明边缘画面、纹理复用和释放、切换后正式计划不变。
- Android `EffectPreviewBackendTest`：4K 合成在 640×360 Surface 叠加光效及有效非零定向模糊，无问题效果；切换模式不改工程或正式导出检查，停止录制不关闭 GPU 测量。
- `cargo run --locked -p motion-render --bin effect_preview_probe -- artifacts/effect-preview`：生成报告和前后 PNG，输出目录不要入 Git。

本地检查：workspace 的 165 项 Rust 测试全部通过；最后修改后复跑 5 项预览/计时测试通过。Android arm64-v8a、x86_64 原生编译、Debug/测试 APK、单元测试及 lint 通过。API 35 SwiftShader/Vulkan 模拟器上的 4 项定向回归通过，包含上面的 4K 效果链、视频预取与准确寻帧、预览档位切换不改全分辨率 PNG，以及 wgpu/GLES 的编码视频对照；这不是手机性能验收。

Probe 使用逐帧上传的合成 4K YUV420 输入，覆盖 4K 合成和缩小到 1080p 的 4K 图层。比较同为均衡模式的旧尺寸/密度路径与新路径，4 帧预热、20 帧测量，输出 1080×608。定向模糊默认长度为 0，测量设置为 100 像素，其余效果为默认参数。计时期间不回读图像，最后保存 PNG；同步等待只用于离线 probe，运行时不使用。

Vivo Y300 Pro 的验收应使用用户的实际 3840×2160、30 fps 视频，分别启停光效、定向模糊和叠加链，记录实际呈现帧率、GPU 时间、视频 pending、PSS 和温控。重点测默认自动模式、持续播放、缩放图层、拖动参数、随机寻帧及 PNG/MP4 输出；桌面数据不能替代此步骤。
