# 效果预算与采样循环核对

预算归类与 shader 优化以主分支 `fa746d8` 为基准。调整图层两张 RGBA8 累加器单独使用 128 MiB 合成预算；效果与蒙版临时纹理合计仍受 64 MiB 检查。这里的数字是宿主资源策略，不能理解为硬件显存容量，也没有将所有纹理池合并为一个新的设备预算。

- 3840×2160 的两张累加器为 63.28 MiB，占 64 MiB 的约 98.9%。原检查把它和效果临时纹理相加，错误拒绝本来分别合规的资源。
- Kotlin 使用两条独立检查，错误分别定位到累加器或效果临时纹理。合并成一条 `&&` 检查虽能改变阈值，仍不便定位哪一项失败。
- `check_scratch` 已在每个效果资源规划时执行；没有新增重复检查。已有逐效果超 64 MiB 的测试断言仍正确。
- 默认参数的全尺寸 4K Motion Tile 可通过规划；Tint 当前需要三张中间纹理，共 94.92 MiB，Gaussian Blur 同样超过 64 MiB。B2 需选实际符合 scratch 预算的效果，不能假定“只有一个效果”就必然合规。这次归类不承诺所有 4K 效果都可运行。

插件校验要求 `for` 使用字面量上下限和单位递增。直接改成 `-n..n` 会被拒绝。优化保留原静态上限，使用动态采样索引与提前退出：

```wgsl
let n=min(128,i32(ceil(radius)));
for(var tap:i32=0;tap<=256;tap=tap+1){
    if tap>2*n{break;}
    let i=tap-n;
    // 原来的 step、距离过滤与累加代码继续使用 i。
}
```

半径不超过 128 时，原距离过滤的有效索引恰好是 `-ceil(radius)..ceil(radius)`；半径超过 128 时保留全部 257 个候选索引，因此无需改变稀疏 step，也避免浮点除法推导边界的舍入差异。Fast Box Blur 使用 `spread=radius*sqrt(iterations)`，默认三次迭代且 radius=4 时为 15 次采样；iterations=1 时为 9 次。Simple Choker 同样保留正负方向、分数 choke 与 Alpha 比较的顺序。

核心效果发布为 1.4.1。1.4.0 原包字节加入历史包注册；1.0.0–1.3.0 不修改。既有工程继续解析原版本与哈希；新版本需显式升级。`builtin::build` 的 stale 检查原来只比较 manifest，且发生于包加载，并不是编译期源码校验。新增回归检查所有打包 WGSL 与工作树源码一致，覆盖仅修改 shader 却漏打包的情况。

验证使用计划预算测试、正常尺寸像素样本、1.4.0/1.4.1 同参数逐字节对照，以及 GPU 预览探针。桌面探针只报告该适配器上的 GPU/CPU 时间，不能据此声称手机 FPS。

设备预算分档与视频流水线优化后续独立处理；这里不调整设备预算、粒子格式、密度重试或严格模式的失败语义。

2026-10-09 本地结果：36 项相关 Rust 用例通过，Android JVM 测试与 lint 通过。RTX 4070 Laptop / Vulkan、相同预览密度下，Gaussian Blur 0.215→0.108 ms，Fast Box Blur 0.256→0.127 ms，Unsharp Mask 0.259→0.133 ms，Simple Choker 0.236→0.135 ms。四项截图完全相同。这些结果仅适用于该桌面样本，未测手机解码、显示节奏或真机帧率。
